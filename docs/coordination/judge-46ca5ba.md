## needs a product decision (not a fix)

1. Trust boundary of the diff: should propose_change expose mdin_after / a unified diff to the agent, or is 'the human sees the diff, the agent sees only validator verdicts' deliberate? If deliberate, say so in the tool description so a tool-table-only agent stops looking for it. (Cost 7's page-side render for the human is a fix either way.)
2. plan_sampling on runs already ≥ min_run_ps: should 'extend this run' be an actionable suggested_edits, or is the product position that more independent runs is always the recommendation and the within-run projection is informational only? (Cost 5.)
3. Which number is the headline of a run page: the run's own ΔG (−19.20, the most negative of nine) or the ensemble estimate (−18.0 ± 0.2 SEM, n=9) with the run's value subordinate. The ±0.66 story argues for the latter; the 'record of one run' framing argues for the former. Related: which spread to quote — all 9 runs (±0.66, includes a 2 ps and four 5 ps runs) or the ≥ 10 ps stratum (±0.79, n=5); explain_result quotes 0.66 while plan_sampling plans on 0.79, and a reviewer will ask why. And whether 2 ps / 5 ps runs count as 'independent runs' for the sign-robustness claim at all, or are shown but excluded from sign/spread statements.
4. Whether non-oracle sanity guards (nstlim > 0, ntwx > 0, temp0 change flagged material) may live in propose_change, or whether every rule must first land in check_amber.py per the oracle-pinning invariant. (Cost 6.)
5. Whether the page itself should state the MMPBSA warning's quantified residual (0.007 % of ΔG) or keep that behind explain_result to preserve the agent's role. (Cost 3.)
6. Is the Tool Console's raw JSON dump the intended human surface? Call renders JSON.stringify(result, null, 1) in a `<pre>` inside a 380 px sidebar (explain_result is ~10 KB) while the one-line summaries live in a separate 'Tool calls' card; decide which is the reader's primary and design the other as secondary.
7. Is the compare page a destination or a transient? Its h1 uses ids ('1l2y-rep4 vs 1l2y-rep3') while run pages use titles, and there is no pair picker — the only way to change the pair is Back → 'compare with…'.
8. Should a run whose verdict is 'drifting' (1l2y-rep2, 2 ps: 'halves -18.2987 → -17.1376 · drifting') present its headline number identically to a converged one? Today .big is the same weight and colour regardless. Related: should 'input checks PASS' stay a neutral grey badge (defensible 'not evidence of accuracy' stance) while WARN/FAIL are coloured, given it reads as unstyled next to seven identical badges?
9. Empty states and width: Contacts 'no PLIP profile for this run' occupies a half-height card beside the tallest card on the page (~400 px void at 1440); decide whether absent artifacts collapse to a one-liner or keep a grid slot, and whether the page gets a max content width (at 2560 cards stretch to ~2070 px with the sidebar 300 px away).
10. Generalisation: the validator and bundle are AMBER-specific and the record is MM-GBSA-specific; whether that is the intended scope or a first target should be stated on the landing page.
11. Not verified by any judge (no real WebMCP client): tool registration in Chrome/ChatGPT, the populated Proposals panel and Approve click, the reanalysis line and sparkline window, and the bundle download. ## praise (what all three judges credited)

The numbers are earned and the tools are not a fetch wrapped in registerTool. recompute_result re-analyses archived per-frame energies over an arbitrary window in the browser and reproduces mmgbsa.dat to the last digit (Δ 0, per-term means summing exactly to −19.1953), then gives −19.35 ± 0.27 with discard_ps 6 and an honest 'too short to judge' on the 5 ps run; the corrected SEM, N_eff, n_needed and the 37.1 ps projection all check by hand, and the autocorrelation time comes out at ≈0.2 ps in both a 30 ps run sampled every 0.3 ps and a 5 ps run sampled every 0.05 ps. explain_result's brief is the best copy on the site — quote ±0.66 run-to-run, not the 0.17 per-frame SEM — and it quantifies the MMPBSA 'HIGHLY QUESTIONABLE' warning (DIHED residual, 0.007 % of ΔG, 'cause is not recorded in the artifacts') instead of hiding it; no entropy, single trajectory and 'not evidence of convergence or physical accuracy' are stated outright. Every projection is labelled 'expected' with assumptions and 'Nothing was run'; the drifting regression run refuses a single-run projection; the 4-frame window and the single 3HTB run degrade to honest fallbacks rather than inventing a spread; the cross-system compare refuses a ΔΔG in one plain sentence, and the same-system compare gives '|ΔΔG| = 0.56 kcal/mol vs run-to-run SD 0.66 (0.9×)', exactly the sentence a reviewer wants. Errors are written for agents (wrong stage lists valid stages, discard_ps 50 says 'use a value below 30', seed 'random' lists the enum, numeric nstlim coerced). The approval invariant held under every trap tried: a dt=0.004 edit cannot be approved, a bundle built before Approve applied nothing, an approved proposal on another run was excluded, and the approved one lands in applied_proposals with the README naming the fork; plan_sampling handing propose_change a ready nstlim while insisting it proposes nothing is the cleanest expression of agent-proposes/human-approves any judge had seen. Every tool call also moves the page (route, compare view, reanalysis state). The mechanical design rules hold: smallest font 13 px, no uppercase or tracking, a 22 px hero that never breaks layout, a non-sticky header, sentence-case copy, and a truthful 'no WebMCP here' empty state rather than a fake 'connected'.
